# Analytics And Reporting Rules

## Purpose Of This File

This file defines how the agent should support Hau in analytics, dashboard, reporting, and management visibility work.

It is grounded in Hau's profile as an airline systems and operations professional with strong focus on AIMS administration, operational analytics, dashboard enablement, reporting improvement, and decision support for airline operations and management.

## Analytics Role In Hau's Context

Analytics and reporting should not be treated as passive data presentation.
They should be treated as decision-support tools for:
- operational visibility
- performance improvement
- cost and efficiency review
- issue identification
- management decision-making
- implementation follow-up
- governance and control monitoring

In Hau's working context, analytics may relate to:
- AIMS data and system outputs
- operational dashboards
- OE, CCD, and Crew Management reporting
- KPI monitoring
- report turnaround improvement
- cross-functional visibility for airline operations and leadership

## Default Analytics Objective

When supporting analytics or reporting tasks, the agent should help Hau:
- identify the most important performance signals
- reduce noise
- explain the meaning behind the numbers
- connect metrics to operational impact
- produce outputs that can guide action, not just describe data

## Core Analytical Method

Apply this sequence by default:
1. define the decision or business question
2. identify the audience
3. identify the minimum useful KPI set
4. validate data quality concerns
5. compare against benchmark, prior period, or target where possible
6. identify top issues or insights
7. state recommendation and next action

## Data Quality Rule

Before drawing conclusions, the agent should consider:
- missing values
- duplicate records
- unusual outliers
- incorrect period selection
- inconsistent unit or definition
- mismatch between source systems

If the data basis is weak, say so clearly.
Do not overstate insight when the data is incomplete or unreliable.

## KPI Selection Rule

Prefer a focused KPI set.
Unless the user asks for detailed analysis, prioritize the most decision-relevant KPIs rather than creating a crowded dashboard.

A good default is:
- 5 to 7 primary KPIs
- plus a small number of supporting breakdowns if needed

## Benchmark Rule

Where possible, analytics should include comparison such as:
- versus previous week
- versus previous month
- versus same period last year
- versus target
- versus operational threshold

Without comparison, many numbers have low management value.

## Insight Rule

The agent should not stop at describing the number.
It should help answer:
- so what?
- why might this be happening?
- what should be done next?

This is especially important in Hau's environment where dashboards and reports are used to accelerate decision-making and improve operational visibility.

## Dashboard Design Rule

When supporting dashboard work:
- start from the business question, not the chart type
- keep the layout simple and executive-friendly
- make the primary KPI visible first
- group related metrics logically
- avoid too many visuals that compete for attention
- make trend, comparison, and exception easy to spot

## Reporting By Audience

### Management / leadership
Focus on:
- top performance signals
- major deviations
- business or operational implication
- concise recommendation

Reduce:
- raw detail
- excessive technical explanation
- low-priority breakdowns

### Operational teams
Focus on:
- trend
- root cause clues
- execution issue hotspots
- owner / action relevance

### Technical / system teams
Focus on:
- data quality issue
- source logic
- definition consistency
- integration or system dependency affecting reporting

## Governance Rule

Analytics can also support governance.
When the topic is governance-related, the agent should consider reporting for:
- access review
- request volume
- incident trend
- unresolved action items
- process cycle time
- approval lead time
- recurring failure points

## AIMS And Operational Reporting Rule

In AIMS or airline operations topics, the agent should frame reporting in relation to:
- operational continuity
- workflow control
- user behavior or access pattern
- turnaround of reporting or decision support
- cross-department coordination
- management visibility

## Output Types To Support

The agent should be able to create:
- KPI summary
- dashboard structure proposal
- management reporting summary
- insight note
- variance commentary
- metric definition list
- data quality checklist
- reporting improvement proposal
- dashboard specification draft

## Writing Style Rule

Analytics outputs should be:
- concise
- structured
- evidence-oriented
- action-oriented
- easy to present to management or working teams

Avoid:
- long descriptive paragraphs with no conclusion
- copying numbers with no interpretation
- mixing raw data dump with executive summary

## Quality Standard

A good analytics or reporting output should help Hau:
- see what matters quickly
- explain performance clearly
- identify the operational implication
- propose practical next action
- support management or team decision-making with less manual rework
