# Risk Register Template

Use this template when Hau needs to identify, track, and manage risks related to implementation, system changes, access governance, reporting, vendor dependency, process design, or operational readiness.

The purpose of this template is to make risks visible early and connect them to ownership, mitigation, and follow-up.

---

# [Risk Register Title]

## 1. Context
State briefly what this risk register relates to.
Examples:
- AIMS implementation phase
- access governance improvement project
- dashboard rollout
- vendor dependency review
- SOP / process transition

## 2. Risk Register Table

Use this baseline structure:
- ID
- Risk Title
- Risk Description
- Category
- Cause / Trigger
- Impact
- Likelihood
- Severity / Rating
- Mitigation Action
- Contingency / Fallback
- Owner
- Status
- Review Date
- Note

### Guidance For Each Column

**Risk Title**
Use a short label that is easy to scan.

**Risk Description**
State the risk clearly in operational or business terms.

**Category**
Examples:
- operational
- system
- access / governance
- data / reporting
- vendor
- implementation
- timeline
- resource

**Cause / Trigger**
State what may create or activate the risk.

**Impact**
Describe the consequence if the risk materializes.
Examples:
- operational disruption
- project delay
- control weakness
- inaccurate reporting
- user access issue
- vendor dependency impact

**Likelihood**
Use a simple scale such as Low / Medium / High unless the user requests another method.

**Severity / Rating**
Can be High / Medium / Low or a score if needed.

**Mitigation Action**
State what should be done to reduce the risk.

**Contingency / Fallback**
State what should happen if the risk occurs despite mitigation.

**Owner**
State who is accountable for monitoring and follow-up.

**Status**
Examples:
- Open
- Monitoring
- Mitigating
- Closed
- Escalated

**Review Date**
State the next review timing if relevant.

## 3. Top Risks Summary
After the table, summarize the top high-priority risks.
Focus on:
- what matters most now
- what may block progress
- what may require management attention

## 4. Escalation Criteria
Where useful, define when a risk should be escalated.
Examples:
- risk rating becomes high
- mitigation fails
- target date is at risk
- operational impact becomes immediate
- vendor response remains unresolved

## 5. Management Attention Items
List risks that require:
- decision
- resource support
- timeline reset
- priority alignment
- cross-department intervention

---

## Short Risk Register Mode

When the user needs a compact version, reduce the table to:
- Risk
- Impact
- Likelihood
- Mitigation
- Owner
- Status

## Writing Rules For This Template

When using this risk register template:
- write risks in practical terms
- link risks to real business or operational effect
- assign clear ownership
- include mitigation, not just description
- avoid theoretical risk language with no execution relevance

## Quality Standard

A good risk register should help Hau:
- see the main risks early
- discuss them clearly with stakeholders
- decide where to mitigate or escalate
- track whether risks are being managed effectively
