# Action Log Template

Use this template when Hau needs to track actions after meetings, workshops, issue reviews, implementation sessions, vendor follow-ups, or internal alignment discussions.

The purpose of this template is to make follow-up clear, visible, and accountable.
It should support practical execution rather than become a passive note list.

This aligns with Hau's preferred output style: short, logical, usable immediately, and focused on action and decision support fileciteturn22file1.

# [Action Log Title]

## 1. Context
State briefly what this action log relates to.
Examples:
- AIMS implementation workshop
- user access process review
- vendor issue escalation follow-up
- dashboard/reporting improvement initiative

## 2. Action Log Table

Use this baseline structure:
- ID
- Action Item
- Background / Reason
- Owner
- Support / Stakeholder
- Due Date
- Priority
- Status
- Dependency / Risk
- Next Step / Comment

### Guidance For Each Column

**Action Item**
Write the action clearly as a deliverable or next step.
Examples:
- confirm access approval flow
- provide vendor clarification on reporting logic
- prepare SOP draft for review
- validate dashboard KPI definitions

**Background / Reason**
Explain briefly why the action exists.
This prevents loss of context during follow-up.

**Owner**
State the main accountable person or team.
The owner should be visible and realistic.

**Support / Stakeholder**
List supporting departments or teams where useful.

**Due Date**
Use a clear date or timeline marker.

**Priority**
Use simple categories unless the user asks otherwise:
- High
- Medium
- Low

**Status**
Examples:
- Open
- In Progress
- Pending Vendor
- Pending Internal Approval
- Closed
- On Hold

**Dependency / Risk**
Capture what may delay or block the action.
Examples:
- waiting vendor input
- pending department confirmation
- system limitation under review
- management approval required

**Next Step / Comment**
State the latest follow-up direction or note.

## 3. Open High-Priority Items
After the table, summarize the most important open items.
This is especially useful when preparing updates for management or project review.

## 4. Escalation Notes
Where relevant, capture actions that need escalation due to:
- overdue timeline
- unresolved vendor response
- unclear ownership
- implementation dependency
- operational impact

## 5. Review Cadence
If useful, state how the action log should be reviewed.
Examples:
- daily until closure
- weekly project meeting
- post-vendor response review

---

## Short Action Log Mode

When the user needs a compact version, reduce the table to:
- ID
- Action Item
- Owner
- Due Date
- Status
- Note

## Writing Rules For This Template

When using this action log template:
- make each action specific
- avoid generic items like "follow up" without object or purpose
- make ownership visible
- make blocking dependencies easy to identify
- write in a way that supports real tracking and accountability

## Quality Standard

A good action log should help Hau:
- know who does what next
- track unresolved issues cleanly
- follow up with vendors or internal teams faster
- escalate the right items at the right time
- reduce ambiguity after workshops or meetings
