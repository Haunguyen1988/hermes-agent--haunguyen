# SOP Access Request Template

Use this template when Hau needs to prepare or standardize the process for user access request, access change, role assignment, modification, review, or revocation.

The purpose of this template is to support access governance, clear responsibility, traceable approval, and controlled system administration.

---

# [Access Request SOP / Procedure Title]

## 1. Purpose
State the purpose of the access request process.
Examples:
- ensure controlled creation and modification of user access
- define approval and execution responsibility
- maintain traceability and governance over system access

## 2. Scope
Define the systems, users, departments, or scenarios covered.
Examples:
- new user creation
- role change
- access amendment
- temporary access
- user deactivation
- periodic access review

## 3. Definitions
List only necessary terms.
Examples:
- requester
- approver
- AIMS PIC
- ICT administrator
- key user
- privileged access

## 4. Responsibilities
Separate responsibilities clearly.
Recommended categories:
- Requester
- Department Manager / Approver
- AIMS PIC / Coordinator
- ICT / System Administrator
- Key User
- Vendor / Support Team if applicable

For each role, define what they must do.

## 5. Access Request Process

### 5.1 Request Initiation
Describe how the request is raised.
Include what information is required.

Typical information:
- user full name / employee ID
- department
- role or function
- requested access scope
- reason for request
- effective date
- manager approval reference

### 5.2 Review And Verification
Describe what should be checked before approval or setup.
Examples:
- completeness of request
- role appropriateness
- segregation of duty concern
- duplicate or unnecessary access

### 5.3 Approval
Describe who approves and what must be approved.
Make approval authority explicit.

### 5.4 Access Setup / Change Execution
Describe who performs the system action.
Include what should be configured, created, amended, or revoked.

### 5.5 Confirmation To User / Department
Describe how completion is communicated.
Include confirmation of effective access if relevant.

### 5.6 Record Retention / Tracking
Describe what records must be maintained.
Examples:
- request form
- approval email
- system ticket
- access log
- tracker entry

## 6. Special Cases / Exceptions
Describe how to handle:
- urgent request
- temporary access
- contractor or third-party access
- failed or incomplete request
- access removal for resignation or transfer

## 7. Access Review / Revocation Control
Where relevant, define:
- periodic review responsibility
- trigger for access removal
- revocation process for inactive or transferred users

## 8. Forms / Templates
List the supporting forms or templates.
Examples:
- access request form
- approval matrix
- role mapping table
- access review checklist

## Writing Rules For This Template

When using this access request SOP template:
- make approval and execution roles distinct
- support traceability
- include governance logic, not only setup steps
- make exceptions visible
- write in a way that supports auditability and operational control

## Quality Standard

A good access request SOP should help Hau:
- standardize access handling
- reduce ambiguity between business and technical roles
- improve governance and traceability
- support secure and controlled system administration
