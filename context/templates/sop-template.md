# SOP Template

Use this template as the default baseline when creating or restructuring an SOP for Hau.

---

# [Document Title]

## 1. Purpose
State the purpose of this SOP clearly and directly.
Explain what process or control the document is intended to establish, standardize, or support.

## 2. Scope
Define where and to whom this SOP applies.
Include departments, functions, systems, locations, or activities if relevant.

## 3. Definitions
List only definitions that are necessary for clarity.
Prefer brief formal definitions for system names, roles, or key terms.

## 4. Responsibilities
Clearly identify each responsible party and what each party is expected to do.

Recommended style:
- [Role / Department]: [clear accountability statement]
- [Role / Department]: [clear accountability statement]

Where needed, distinguish between:
- requester
- approver
- PIC / coordinator
- ICT / system administrator
- key user
- vendor / support

## 5. Procedure
Write the procedure in logical sequence.
Use numbered clauses or sub-clauses when the workflow is formal or cross-functional.

Recommended structure:
### 5.1 Trigger / Initiation
Describe how the process starts.

### 5.2 Review / Verification
Describe what must be checked and by whom.

### 5.3 Approval
Describe what requires approval and who gives it.

### 5.4 Execution
Describe the core action steps.

### 5.5 Confirmation / Handover
Describe how completion is confirmed and handed over.

### 5.6 Record / Filing / Tracking
Describe what must be recorded, retained, or tracked.

## 6. Escalation / Control / Exception Handling
Describe escalation paths, exception handling, control points, or contingency actions if relevant.

Examples:
- issue escalation path
- urgent request handling
- service failure handling
- approval exception
- audit or verification control

## 7. Records
State what records or evidence must be maintained.

Examples:
- request form
- approval email
- system log
- tracker entry
- vendor ticket
- archived file

## 8. Appendix
Add supporting templates, forms, matrices, or examples when needed.

Examples:
- Appendix A: request template
- Appendix B: approval matrix
- Appendix C: access role table
- Appendix D: incident report form

---

## Writing Rules For This Template

When using this SOP template:
- keep the language formal and practical
- make responsibilities explicit
- avoid long narrative paragraphs where procedural steps are clearer
- preserve operational control points
- use clean numbering when the document is formal
- make the output easy to convert into a Word-ready internal document

## Optional Internal Document Layer

If the user asks for stronger internal formatting, shape the content so it can later support:
- cover page
- document code
- version number
- approval matrix
- document control table
- header/footer
- appendix references
