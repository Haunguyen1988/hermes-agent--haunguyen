# Issue Escalation Template

Use this template when Hau needs to escalate a system issue, service interruption, operational incident, recurring malfunction, or unresolved support case.

The purpose of this template is to make escalation clear, structured, and actionable for internal teams, ICT, vendor, or management.

---

# [Issue Escalation Title]

## 1. Issue Summary
Provide a short summary of the issue.
State what happened in clear operational language.

Examples:
- users unable to access module
- report output incorrect since [time]
- interface data not updating
- service unstable during operational use

## 2. Time / Reference Information
State the relevant timing information.
Examples:
- date and time detected
- duration
- affected period
- related ticket or incident reference number

## 3. Affected Area
Describe what is affected.
Examples:
- system / module
- department
- user group
- workflow
- station / operation if relevant

## 4. Business / Operational Impact
Explain why the issue matters.
Focus on practical effect.

Examples:
- disruption to operational workflow
- inability to complete required action
- manual workaround needed
- delay in reporting or decision-making
- risk to operational continuity

## 5. Current Status
State what is known now.
Examples:
- under investigation
- workaround applied
- awaiting vendor response
- issue intermittent
- impact contained / not yet contained

## 6. Actions Already Taken
List what has already been done.
Examples:
- issue verified with users
- screenshot / log captured
- ICT informed
- vendor ticket raised
- temporary workaround communicated

## 7. Required Support / Escalation Request
State clearly what support is required.
Examples:
- urgent investigation
- workaround recommendation
- ETA for resolution
- root cause analysis
- configuration review
- management support for priority handling

## 8. Evidence / Attachments
List available supporting evidence.
Examples:
- screenshot
- error log
- report sample
- email trail
- incident ticket

## 9. Owner / Follow-Up Point
State who is coordinating the issue and who should respond.
Examples:
- AIMS PIC
- ICT focal point
- vendor support contact
- department representative

## 10. Next Update / Follow-Up Expectation
State the expected next step or next update timing if known.

---

## Short Escalation Email Mode

When the user needs a quick escalation email, use this sequence:
- issue summary
- affected area and impact
- actions already taken
- specific support required
- request for update / ETA

## Major Incident Mode

If the issue is high severity, add:
- severity level
- wider business impact
- workaround status
- communication requirement to stakeholders
- recovery validation expectation
- RCA expectation after service restoration

## Writing Rules For This Template

When using this issue escalation template:
- write facts first
- keep the impact visible
- avoid emotional language
- distinguish confirmed issue from suspected cause
- ask clearly for the required response
- make follow-up ownership visible

## Quality Standard

A good escalation output should help Hau:
- communicate the issue quickly and clearly
- align ICT, vendor, and business stakeholders
- reduce confusion during issue handling
- track required follow-up and response expectation
- support structured incident management with minimal rework
