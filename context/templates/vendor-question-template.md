# Vendor Question Template

Use this template when Hau needs to prepare structured questions for vendors during clarification, implementation, fit-gap review, issue follow-up, or system capability assessment.

This template is designed to produce question packs that are easy for vendors to answer and easy for Hau to track internally.

# [Vendor Question Pack Title]

## 1. Purpose
State why this question pack is being sent.
Examples:
- clarify system capability before implementation decision
- confirm access model and segregation logic
- validate issue root cause and corrective action
- confirm reporting or integration behavior

## 2. Background / Business Context
Provide a short business or operational context.
Keep this concise.
The vendor should understand why the clarification matters.

Recommended content:
- current situation
- affected process or users
- reason this clarification is needed now

## 3. Current Understanding
State the team's current understanding if applicable.
This helps the vendor confirm or correct it.

Examples:
- our current understanding is that...
- based on previous discussion, we understand that...
- please confirm whether this understanding is correct...

## 4. Questions By Topic
Group questions into logical sections.

Recommended structure:

### 4.1 Capability / Function
Use for feature support, workflow behavior, access logic, report logic, or standard function questions.

Question pattern:
- Can the system support [business use case]?
- If yes, how is this configured or controlled?
- If not, what limitation or alternative exists?

### 4.2 Process / Workflow
Use when the clarification is about how the system supports a business process.

Question pattern:
- How should this process be handled in the system?
- What is the recommended workflow?
- Which user role or module should perform the action?

### 4.3 Access / Data Segregation
Use when the question relates to visibility, role-based access, data scope, or multi-entity structure.

Question pattern:
- Can access be restricted by [airline / department / role / data scope]?
- How is this controlled in standard practice?
- What is the limitation or prerequisite?

### 4.4 Integration / Data Flow
Use when the issue relates to interface, upstream/downstream dependency, or data structure.

Question pattern:
- How does the system exchange or store this data?
- What data field or interface is required?
- Are there existing client examples for this setup?

### 4.5 Issue / Root Cause / Recovery
Use when following up an issue or service problem.

Question pattern:
- What is the identified root cause?
- What corrective action is recommended?
- What workaround is available until permanent resolution?
- What is the expected timeline?

### 4.6 Implementation / Timeline / Dependency
Use when the clarification affects readiness or project plan.

Question pattern:
- What dependency must be resolved first?
- What configuration or setup is required?
- What is the recommended sequence?
- What timeline or effort should be expected?

## 5. Expected Response / Action
State what Hau expects from the vendor.
Examples:
- confirmation of capability
- explanation of limitation
- recommended approach
- issue update and ETA
- clarification before workshop or next review

## 6. Priority / Critical Items
If needed, highlight the questions that are blocking timeline, decision, access setup, or operational readiness.

## 7. Internal Follow-Up Note
Optionally add a short internal note after the question pack to help Hau track:
- which department raised the question
- what decision depends on the answer
- what to do after vendor response

## Short Vendor Email Mode

When the user wants a quick email instead of a full question pack, use this pattern:
- opening sentence with purpose
- short background sentence
- 2 to 5 numbered questions
- closing line stating expected clarification or next action

## Writing Rules For This Template

When using this template:
- ask questions that are specific and answerable
- avoid mixing too many topics in one question
- separate confirmed fact from assumption
- keep business context visible but brief
- highlight urgency only when justified by operational or project impact
- write in formal English when the output is vendor-facing

## Quality Standard

A good vendor question pack should help Hau:
- get clearer answers faster
- reduce misunderstanding with vendors
- track open clarifications cleanly
- support implementation, fit-gap review, or issue resolution effectively
