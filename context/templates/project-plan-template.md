# Project Plan Template

Use this template when preparing an implementation plan, rollout plan, cross-functional project plan, or department-based execution plan for Hau.

The purpose of this template is to turn broad project requests into practical planning structure with clear phases, ownership, deliverables, risks, and next steps.

---

# [Project / Initiative Title]

## 1. Objective
State the objective clearly.
Explain what the project is intended to achieve and why it matters.

## 2. Scope
Define what is included in the plan.
If helpful, also state what is out of scope.

## 3. Stakeholders
List the main stakeholders or groups involved.
Where possible, distinguish between:
- project lead / PIC
- business owner
- approver
- operational departments
- ICT
- vendor / support
- management

## 4. Project Approach / Phases
Break the project into practical phases.

Recommended default structure:

### Phase 1: Initiation / Alignment
Typical content:
- confirm objective
- identify scope
- align stakeholders
- prepare initial requirement / question set

### Phase 2: Assessment / Requirement Clarification
Typical content:
- collect current-state process
- identify requirement by department
- clarify vendor capability
- capture fit-gap points

### Phase 3: Design / Planning
Typical content:
- define target workflow
- confirm ownership and process design
- prepare implementation sequence
- define control points and supporting documents

### Phase 4: Execution / Configuration / Coordination
Typical content:
- perform agreed actions
- coordinate department readiness
- track open points and dependencies
- manage issue escalation

### Phase 5: Validation / UAT / Readiness
Typical content:
- validate process practicality
- confirm business acceptance
- identify remaining gaps or corrective actions

### Phase 6: Go-Live / Handover / Stabilization
Typical content:
- support launch or transition
- monitor issues
- confirm support path
- hand over tracking and operating ownership

## 5. Key Deliverables
List the main outputs expected from the project.

Examples:
- requirement checklist
- fit-gap log
- SOP / process document
- user / access matrix
- action log
- training material
- implementation tracker
- management summary

## 6. Department Workstream View
Where useful, break activities by department.

Suggested format:
- OCC: [main activities]
- Crew: [main activities]
- Maintenance: [main activities]
- Ground Ops: [main activities]
- ICT: [main activities]
- Vendor: [main activities]

## 7. Dependencies And Risks
Identify major dependencies and risks.
Focus on items that may affect scope, timeline, quality, access, coordination, or operational readiness.

Examples:
- vendor clarification delay
- incomplete process mapping
- unclear approval flow
- resource availability
- system limitation
- dependency on another department or project

## 8. Governance / Tracking Method
State how the project will be tracked.

Examples:
- weekly review meeting
- action log
- fit-gap tracker
- risk register
- escalation path
- management checkpoint

## 9. Immediate Next Steps
State the next practical actions.
Use short action-oriented wording.

---

## Optional Tracker Table

When a table is needed, use this baseline structure:
- ID
- Work Item
- Description
- Owner
- Support
- Due Date
- Status
- Risk / Dependency
- Next Step

## Writing Rules For This Template

When using this project plan template:
- keep phases practical, not theoretical
- make ownership visible
- make dependencies and risks explicit
- adapt detail level to audience
- for management, compress detail and highlight phase, risk, and decision points
- for working teams, include clearer execution detail

## Quality Standard

A good output created from this template should help Hau immediately:
- explain the project structure
- run a meeting
- align departments
- ask the right vendor questions
- start tracking execution with minimal rework
