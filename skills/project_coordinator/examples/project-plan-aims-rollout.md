# Example — AIMS Rollout Plan

## Use Case
Create a phased project plan for implementing or expanding AIMS use across operational departments.

## Example Prompt
Create a practical project plan for AIMS rollout across OCC, Crew, Maintenance, Ground Ops, ICT, and vendor support.
Use phase-based structure and include deliverables, risks, and next steps.

## Example Output

# Project Plan — AIMS Operational Rollout

## Objective
Implement and align AIMS usage across key operational departments in a controlled, phased manner.

## Main Phases
### Phase 1: Initiation And Alignment
- confirm scope
- identify stakeholders
- align project objective and working model

### Phase 2: Requirement And Current-State Review
- collect department workflows
- identify current pain points
- capture access, reporting, and process requirements

### Phase 3: Fit-Gap And Design
- compare current workflow and target usage
- confirm system logic with vendor
- define target process and ownership

### Phase 4: Execution And Coordination
- perform setup / configuration actions
- track open questions and dependencies
- prepare working documents and SOP drafts

### Phase 5: Validation And Readiness
- test workflow practicality
- confirm department acceptance
- close key open items before go-live

## Key Risks
- unclear ownership across departments
- incomplete vendor clarification
- access approval not finalized
- process change not communicated consistently

## Immediate Next Steps
- confirm workshop sequence by department
- prepare vendor clarification pack
- create fit-gap log and action tracker

## Why This Is A Good Example
- phase-based practical rollout planning
- suitable for Hau's implementation coordination work
