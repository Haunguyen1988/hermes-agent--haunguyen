# SOP Writer Skill

## Purpose

Use this skill to create, optimize, or rewrite SOPs and other internal operational documents for Hau.

This skill is designed for airline-related operational documentation and should produce outputs that are practical, structured, reusable, and ready to paste into Word or internal templates with minimal editing.

## When To Use

Use this skill when the task involves:
- drafting a new SOP
- converting notes, bullets, or chat content into formal procedure
- rewriting an SOP into more professional English or Vietnamese
- shortening, tightening, or simplifying an SOP
- restructuring content into internal document format
- adding or improving responsibilities, workflow, controls, records, forms, or appendices
- preparing Word-ready internal documentation content

## Primary Objective

Turn raw information into a document that is:
- clear
- formal
- operationally usable
- internally structured
- easy for Hau to reuse or extend

## Default SOP Writing Principles

Always apply these principles unless the user asks otherwise:
- write for operational use, not for academic reading
- keep sentences clean and direct
- prefer structured clauses over long paragraphs
- use clear section hierarchy
- make responsibilities explicit
- make workflow logic visible
- include records, forms, or evidence where useful
- reduce vague wording such as "as necessary" or "if required" unless truly needed
- keep the tone professional and internal-business appropriate

## Default SOP Structure

When the user does not specify structure, prefer this order:
1. Purpose
2. Scope
3. Definitions
4. Responsibilities
5. Procedure / Workflow
6. Escalation / Controls / Records
7. Appendix / Template / Form

## Internal Document Upgrade Mode

When the user asks for a more formal internal version, shape the content so it can support:
- cover page
- document code
- version
- approval matrix
- document control table
- header/footer
- appendix section

In this mode, the output should still stay content-focused, but it must be organized in a way that is easy to place into a final internal document layout.

## Writing By Audience

### Internal operational audience
- include execution detail
- define owner clearly
- define trigger and expected action
- make handoff points visible

### ICT / system support audience
- make roles, access, escalation, and system actions clear
- separate user responsibility from technical support responsibility

### Vendor-facing audience
- use formal English
- keep wording precise
- avoid internal slang or ambiguous shorthand

### Management audience
- compress detail
- highlight control logic, ownership, risk, and decision relevance

## Formatting Rules

Preferred style:
- short headings
- numbered sections when the document is formal
- bullets only when they improve readability
- parallel sentence structure within lists
- responsibilities written as accountable action statements
- workflow steps written in logical sequence

## Optimization Rules

When optimizing an existing SOP:
- remove repetition
- merge overlapping clauses
- tighten language
- simplify without losing control points
- keep operational logic intact
- preserve important approvals, escalations, and records

## Bilingual Rule

When the user requests Vietnamese-English or English-Vietnamese output:
- preserve operational meaning exactly
- do not translate loosely when a formal operational phrase is needed
- keep department and system terms consistent across versions

## Common Output Types

This skill should be able to produce:
- draft SOP
- optimized SOP
- formal English SOP
- internal Word-ready SOP content
- simplified SOP version
- section rewrite such as Responsibilities or Procedure only
- appendix template content

## Quality Standard

A good output from this skill should allow Hau to do one of the following immediately:
- paste it into a document
- send it internally for review
- use it as a working draft with minimal cleanup
- expand it into a final SOP package
