# Example — SOP User Access Creation

## Use Case
Create an internal SOP section for creating a new AIMS user account and assigning the correct access rights.

## Example Prompt
Write a practical internal SOP for AIMS user creation covering request, approval, setup, confirmation, and record retention.
Audience: internal operational departments, AIMS PIC, ICT, and approvers.
Tone: formal, clear, Word-ready.

## Example Output

# SOP — AIMS User Access Creation and Amendment

## 1. Purpose
This procedure defines the standard process for requesting, approving, creating, amending, and recording user access in AIMS in order to ensure controlled access, traceability, and operational continuity.

## 2. Scope
This procedure applies to all requests relating to:
- new user creation
- access role amendment
- temporary access
- access removal for transfer or resignation

## 3. Responsibilities
### 3.1 Requesting Department
- Raise the access request with complete user and role information.
- Confirm the business need and requested access scope.

### 3.2 Department Manager / Approver
- Review the request.
- Confirm the requested access is appropriate for the user's role.
- Approve or reject the request.

### 3.3 AIMS PIC
- Review request completeness and role logic.
- Coordinate with ICT or vendor where required.
- Maintain request tracking and record status.

### 3.4 ICT / System Administrator
- Create or amend the user profile in the system after approval.
- Confirm completion to the AIMS PIC or requesting department.

## 4. Procedure
### 4.1 Request Initiation
The requesting department shall submit a user access request containing:
- user full name
- employee ID
- department
- position / role
- required module or access scope
- reason for request
- effective date

### 4.2 Review And Verification
The AIMS PIC shall review the request for:
- completeness of information
- role appropriateness
- duplication or conflict with existing access

### 4.3 Approval
The department manager or designated approver shall approve the request before any system action is taken.

### 4.4 Access Setup
Upon approval, ICT or the designated system administrator shall create or amend the access in AIMS.

### 4.5 Confirmation
The AIMS PIC or ICT shall confirm completion to the requesting department and user.

### 4.6 Record Retention
The following records shall be retained:
- request form or email
- approval evidence
- system setup confirmation
- access tracker entry

## 5. Special Cases
Urgent access requests shall still require approval. Where immediate action is needed for operational continuity, approval may be confirmed first by email or message and documented formally afterward.
