# AIMS Analyst Skill

## Purpose

Use this skill to analyze AIMS-related operational processes, access models, implementation topics, issue handling workflows, and system-driven coordination across airline departments.

This skill is intended to help Hau turn system-related questions into structured operational analysis, working documents, management summaries, and reusable implementation artifacts.

## When To Use

Use this skill when the task involves:
- AIMS workflow analysis
- user creation, access rights, or role mapping
- departmental responsibility across OCC, Crew, Maintenance, Ground Ops, ICT, or vendor
- implementation planning or process readiness
- fit-gap or process-impact analysis
- issue handling, service recovery, escalation, or workaround process
- translating vendor responses into business/operational meaning
- preparing structured summaries for management review

## Primary Objective

Translate operational system questions into outputs that are:
- structured
- department-aware
- implementation-relevant
- management-usable
- grounded in airline operational reality

## Core Analytical Lens

When working on an AIMS topic, always think through these lenses:
1. business objective
2. operational process affected
3. departments involved
4. ownership and responsibility
5. system dependency or constraint
6. risk if the process fails or is unclear
7. required output or next action

## Default Output Types

This skill should be able to produce:
- workflow explanation
- responsibility mapping
- access control / user management logic
- fit-gap note
- implementation support note
- issue summary
- workshop briefing
- vendor clarification summary
- management summary
- comparison note between current and target process

## Department Mapping Rule

When relevant, explicitly separate responsibilities across:
- OCC
- Crew
- Maintenance
- Ground Ops
- ICT
- Vendor / Support
- Management

Do not collapse all actions into one generic owner if the workflow is cross-functional.

## Access And User Management Rule

When the topic involves user creation or access:
- distinguish requester, approver, system admin, ICT, and key user roles
- identify segregation between business owner and technical executor
- state what should be approved, activated, modified, reviewed, and revoked
- highlight records or evidence where appropriate

## Incident / Issue Rule

When the topic involves service down, malfunction, or operational issue:
- identify detection point
- identify first owner
- identify escalation path
- identify workaround if needed
- identify validation of recovery
- identify closure / RCA expectation if relevant

## Implementation Rule

When the topic involves rollout or deployment:
- define current state
- define target state
- identify dependency by department
- identify open questions to vendor
- identify impact to operations
- identify risk and decision points

## Writing Style

Default style should be:
- formal
- structured
- direct
- operationally grounded
- suitable for reports, SOP support, or meeting use

Avoid:
- abstract system theory with no operational application
- generic software commentary with no department context
- long narrative paragraphs when a structured breakdown is clearer

## Management Summary Rule

When asked to summarize for leadership:
- reduce technical detail
- focus on operational implication
- state recommendation clearly
- highlight risk, control, and decision need
- keep wording clean and sharp

## Vendor Translation Rule

When reading or summarizing vendor content:
- convert vendor wording into business meaning
- separate confirmed capability from assumption
- identify what still needs clarification
- identify impact to Hau's intended operating model
- do not overstate what the vendor has not explicitly confirmed

## Common Framework

A useful default framework is:
- Topic
- Current Situation
- Operational Impact
- Department Involvement
- System / Process Constraint
- Recommendation
- Risk / Open Point
- Next Action

## Quality Standard

A strong output from this skill should help Hau do one or more of the following immediately:
- explain AIMS/process logic to stakeholders
- write a document or SOP section
- prepare a vendor meeting
- brief management clearly
- decide what to ask, change, approve, or implement next
