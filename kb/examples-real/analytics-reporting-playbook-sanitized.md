# Analytics And Reporting Playbook — Sanitized Example

## Document Type
Sanitized real-work playbook derived from Hau's reporting and dashboard style.

## Sanitization Note
This document preserves working approach and reporting logic while removing sensitive KPI values, source details, and confidential business information.

## Purpose
This file helps the agent understand how Hau approaches analytics and reporting tasks in practical business use.

## Reporting Philosophy
Reporting should not only describe the data.
It should help decision-makers understand:
- what matters most
- what changed
- why it matters
- what should happen next

## Default Reporting Sequence
1. confirm the business question
2. check the data basis
3. identify the most important KPI
4. compare with prior period or target
5. highlight top issues or deviations
6. explain possible drivers
7. recommend next action

## KPI Focus Rule
Prefer a focused KPI set rather than many low-value indicators.
A report or dashboard should usually highlight only the most relevant performance signals first.

## Benchmark Rule
Useful reporting normally includes comparison such as:
- previous week
- previous month
- same period last year
- target or threshold

## Insight Pattern
A typical insight note in Hau's style follows this form:
- observation
- implication
- likely cause or hypothesis
- recommended action

### Sample Style
Operational performance improved versus the prior period, but one location / process remains below target.
This suggests that overall recovery is progressing, while a specific execution bottleneck still requires attention.
Recommended next action is to review the contributing process and confirm owner follow-up before the next cycle.

## Dashboard Logic Pattern
A strong dashboard should answer:
- what is the current status?
- where is the biggest deviation?
- which trend needs action?
- who should care?

## Management Summary Pattern
When reporting to management, Hau typically benefits from a compressed structure:
- overall signal
- top deviation
- implication
- recommendation

## Working-Level Summary Pattern
When reporting to operational or technical teams, include:
- more context
- execution hotspot
- owner or action relevance
- possible data quality or integration issue if applicable
