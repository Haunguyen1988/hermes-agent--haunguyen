# Vendor Communication Patterns — Sanitized Example

## Document Type
Sanitized example set derived from Hau's real working style for vendor communication.

## Sanitization Note
This document contains reusable communication patterns only.
It does not include real vendor names, real tickets, real contact details, or sensitive operational data.

## Purpose
This file helps the agent understand how Hau typically wants vendor-facing content to be structured.

The intent is to produce communication that is:
- formal
- concise
- clear in purpose
- easy for the vendor to answer
- strong enough to protect internal business and operational interests

## Pattern 1 — Capability Clarification
### Preferred structure
- short opening purpose
- brief business context
- current understanding
- numbered questions
- expected clarification

### Sample Style
We would like to clarify whether the current platform supports the following operating requirement.
Our current understanding is that the function may be achievable through configuration or role setup.
Please confirm:
1. whether the requirement is supported
2. how it is controlled in practice
3. what limitation or prerequisite exists
4. whether a workaround is needed if the standard function is insufficient

## Pattern 2 — Issue Escalation
### Preferred structure
- issue summary
- time / affected area
- operational impact
- actions already taken
- required support

### Sample Style
We are currently facing an issue affecting [module / workflow] since [time].
The issue is impacting [user group / operational process].
Internal verification has been completed and initial evidence is available.
Please support urgent investigation and advise whether a workaround or ETA can be provided.

## Pattern 3 — Fit-Gap Clarification
### Preferred structure
- current state
- desired state
- gap statement
- clarification request
- implementation relevance

### Sample Style
The current process supports [current state], while the business requires [desired state].
We would like to confirm whether this gap can be addressed through configuration, workaround, or enhancement.
Please also advise any known operational limitation or standard client practice relevant to this scenario.

## Pattern 4 — Follow-Up On Unclear Response
### Preferred structure
- refer to earlier discussion
- restate unresolved point clearly
- narrow the question
- state why the answer matters

### Sample Style
Thank you for the previous clarification.
However, one key point remains unclear from an operational and governance perspective.
Please confirm specifically whether [point] is controlled by [role / configuration / process], and whether any limitation applies in day-to-day use.
This clarification is important for our internal decision and implementation planning.

## Pattern 5 — Management-Usable Internal Translation
After receiving a vendor answer, Hau often needs a short internal summary in this form:
- confirmed points
- open points
- operational implication
- recommended next action

- converting vendor response into internal summary
